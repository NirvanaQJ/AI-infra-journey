## 两条规则
1. 成员对齐：每个成员落在「自身大小整数倍」的地址上
2. 整体对齐：结构体总大小是最大成员对齐值的整数倍（尾部 padding）

## 实测数据
| 结构 | sizeof | 原因 |
|---|---|---|
| A (char/int/char) | 12 | |
| B (int/char/char) | 8 | |
| NetHdr (packed) | 7 | |
| NetHdrRaw | 8 | |

同样成员换个顺序差 4 字节；100 万个差 __ MB。

## 与方向的交点（重点）
网络协议头必须紧密排列 —— 线上字节流没有 padding。
所以 RDMA 的 BTH、以太网头定义要么用 `__attribute__((packed))`，要么手工排成员。
这和周二的「网络字节序是大端」是同一类问题：**内存里的布局 ≠ 线上字节流**。

## offsetof 怎么用
`#include <stddef.h>`，`offsetof(struct A, i)` 返回成员相对结构体起始的字节偏移。
这是调查 padding 的标准工具。
