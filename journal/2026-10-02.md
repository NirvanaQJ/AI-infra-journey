## 从源码到 `.o`

`main.c` 声明并使用 `value`、`bump`；`helper.c` 分别用 `int value = 3` 和 `int bump(int x) { return x + 1; }` 提供定义。对两个 C 文件分别执行 `gcc -O0 -fno-pie -fno-stack-protector -c`，得到 `main.o`、`helper.o`。`readelf -h main.o` 显示类型为 `REL`，说明它还可以被链接器重新安排位置，不是最终可执行文件。

## 符号解析：`UND` 找到定义

[`03-main-symbols.txt`](../exercises/c/linking-oct02/03-main-symbols.txt) 显示 `main.o` 中 `value`、`bump` 均为 `UND`；[`04-helper-symbols.txt`](../exercises/c/linking-oct02/04-helper-symbols.txt) 显示 `helper.o` 提供 `OBJECT value` 和 `FUNC bump`。所以本例的符号解析是把前者的两个未定义引用分别匹配到后者的定义。最终可执行文件的符号表中，`value=0x403000`、`bump=0x401025`。

## 重定位：找到定义后修正指令

[`05-relocations.txt`](../exercises/c/linking-oct02/05-relocations.txt) 中，`.rela.text` 对 `value` 的记录位于偏移 `0x0a`、类型为 `R_X86_64_PC32`；对 `bump` 的记录位于偏移 `0x11`、类型为 `R_X86_64_PLT32`。[链接前反汇编](../exercises/c/linking-oct02/06-before-link.txt) 可见读取 `value` 和调用 `bump` 的位移仍是占位值。

链接后，[反汇编](../exercises/c/linking-oct02/08-after-link.txt) 中读取变量的指令为 `mov 0x1fe4(%rip),%eax # 403000 <value>`。该指令下一条地址是 `0x40101c`，计算 `0x403000 - 0x40101c = 0x1fe4`，与写入的位移一致。调用指令为 `call 401025 <bump>`：下一条地址 `0x401023`，目标地址 `0x401025`，位移为 `2`。这两处分别给出数据引用和函数调用的重定位实例。

## 手动 `ld` 链接与运行结果

直接使用 `ld` 需要显式提供入口。本练习把 [`start.S`](../exercises/c/linking-oct02/start.S) 编译为 `start.o`；其中 `_start` 调用 `main`，再用 Linux x86-64 的 `exit` 系统调用把返回值作为退出码。完整命令记录在练习 README，关键一步是：

```sh
ld -o build/linking-oct02/manual build/linking-oct02/start.o build/linking-oct02/main.o build/linking-oct02/helper.o
```

`manual` 的 ELF 类型为 `EXEC`，入口地址为 `0x401000`；本例最终文件中 `readelf -r` 报告没有剩余重定位。实际运行 `./build/linking-oct02/manual` 后，`echo $?` 得到 `4`，与 `bump(3)=4` 一致。
