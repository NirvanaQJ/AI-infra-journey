# 2026-09-28（W2 · 周一）

## CSAPP：算术逻辑操作、条件码、比较与测试

### 1. 算术与逻辑指令

沿用 AT&T 汇编写法：**源在前，目标在后**；`l` 表示操作 32 位，`q` 表示操作 64 位。例如 `addl $3, %eax` 将 3 加到 `%eax`，结果写回 `%eax`。

| 指令 | 专业解释 | 通俗理解 |
| --- | --- | --- |
| `subl %esi, %edi` | 计算 `%edi - %esi`，结果写回 `%edi`。 | 从目标盒子里的数减去来源盒子里的数。 |
| `andl $1, %eax` | 对每一位做与运算，结果写回 `%eax`。 | 像筛子一样只留下最低位，可据此看奇偶。 |
| `orl` / `xorl` | 分别对各位做或／异或，结果写回目标。 | 逐格处理两排 0 和 1。 |
| `shll` / `shrl` / `sarl` | 左移／逻辑右移／算术右移；`shr` 从左侧补 0，`sar` 从左侧补原符号位。 | 把所有位挪动；两种右移的“补空格”方式不同。 |
| `leaq 8(%rdi,%rsi,4), %rax` | 将 `%rdi + %rsi × 4 + 8` 写入 `%rax`；不访问该地址中的数据。 | 只算门牌号，不进屋取东西。 |

`add`、`sub`、`and` 等会更新相关条件码；`mov` 和 `lea` 不会。`lea` 因而也常被用来做不影响条件码的整数计算。[Intel 手册：LEA](https://cdrdv2-public.intel.com/789581/325383-sdm-vol-2abcd.pdf)

### 2. 条件码：运算留下的四个常用标志

条件码是 x86-64 `RFLAGS` 寄存器中的状态位。先认识下面四个；它们针对**当前指令的操作宽度**，例如 `addb` 按 8 位计算，`addl` 按 32 位计算。

| 标志 | 专业解释 | 通俗解释 |
| --- | --- | --- |
| `ZF`（Zero） | 运算结果为 0 时置 1。 | “结果是不是零？” |
| `SF`（Sign） | 等于截取后结果的最高位。 | “结果的符号位是不是 1？” |
| `CF`（Carry） | 加法进位或减法借位时置 1，反映无符号运算的范围问题。 | “按无符号数看，有没有进位或借位？” |
| `OF`（Overflow） | 有符号整数的数学结果超出该位宽可表示的范围时置 1。 | “按有符号数看，数值是否溢出？” |

例如按 **8 位**计算：`0x7f + 1 = 0x80`，即有符号的 `127 + 1` 变成位模式表示的 `-128`，所以 `OF=1`、`CF=0`。而 `0xff + 1 = 0x00` 产生了第 9 位进位，所以 `CF=1`；若按有符号数理解为 `-1 + 1 = 0`，则 `OF=0`。[Intel 手册：状态标志](https://cdrdv2-public.intel.com/671436/253665-sdm-vol-1.pdf)

### 3. `cmp` 和 `test`：只检查，不保存计算结果

```asm
cmpl %esi, %edi     # 假想计算 %edi - %esi；只更新条件码
testl %eax, %eax    # 假想计算 %eax & %eax；只更新条件码
```

- **专业解释：** `cmp` 按减法设置标志，但不写回差值；`test` 按逐位与设置标志，但不写回与的结果。`test` 还会将 `CF` 和 `OF` 清零。
- **通俗解释：** `cmp` 是“做一道减法题，只交判断记录”；`test` 是“拿位掩码照一下，只交判断记录”。原操作数不变。
- `testl %eax,%eax` 常用来问 `%eax` 是否为零：非零数与自身逐位与仍是自身，只有零会使 `ZF=1`。
- `testl $1,%eax` 检查最低位；如果 `ZF=1`，说明最低位是 0，也就是这个整数为偶数。

注意 AT&T 操作数顺序：`cmpl $5,%eax` 的“假想减法”是 `%eax - 5`，不是 `5 - %eax`。[Intel 手册：CMP](https://cdrdv2-public.intel.com/782156/325383-sdm-vol-2abcd.pdf)、[TEST](https://cdrdv2-public.intel.com/671110/325383-sdm-vol-2abcd.pdf)

### 4. 条件跳转：根据标志决定下一步

| 指令 | 跳转条件 | 适用理解 |
| --- | --- | --- |
| `je` / `jz` | `ZF=1` | 相等，或检查结果为零。 |
| `jne` / `jnz` | `ZF=0` | 不相等，或检查结果非零。 |
| `jl` | `SF ≠ OF` | 按**有符号数**比较的小于。 |
| `jb` | `CF=1` | 按**无符号数**比较的小于。 |

`cmp` 只产生标志；后面的跳转指令才决定按有符号还是无符号解释。例如 `%eax=0xffffffff`，执行 `cmpl $5,%eax` 后：按有符号 32 位是 `-1 < 5`，所以 `jl` 会跳；按无符号 32 位是 `4294967295 < 5`（不成立），所以 `jb` 不跳。`setcc` 则根据条件把一个字节写成 0 或 1，而不是跳到别处。[Intel 手册：条件码](https://cdrdv2-public.intel.com/671436/253665-sdm-vol-1.pdf)

对照 [9 月 26 日笔记](2026-09-26.md) 中见过的两条指令：

```asm
test %eax, %eax
je   somewhere
```

逐步读：检查 `%eax` → 若它为零则 `ZF=1` → `je` 跳转。`test` 不会把 `%eax` 改成零。

**读反汇编时的三个易错点：**

1. `cmp` 的减法方向是“第二个操作数减第一个操作数”（AT&T 写法）；`cmp` 和 `test` 都不保存假想运算的结果。
2. 跳转读取的是**当前**条件码。`cmp` 后若插入一条会改标志的 `add`，后面的 `je` 看到的就可能是 `add` 留下的标志。
3. `SF=1` 不能单独断定“有符号小于”；还要结合 `OF`。有符号与无符号比较要选对 `jl`、`jb` 这样的跳转条件。

### 自测：先判断，再核对

1. `%eax=0`；执行 `testl %eax,%eax` 后，`jne` 会跳吗？
2. `%eax=6`；执行 `testl $1,%eax` 后，`je` 会跳吗？
3. `%eax=0xffffffff`；执行 `cmpl $5,%eax` 后，`jl` 与 `jb` 哪个会跳？

**答案：**① 不跳，`ZF=1`；② 会跳，因为 `6 & 1 = 0`；③ `jl` 会跳，`jb` 不跳。

以后每读一段相关汇编，依次问：**操作宽度是多少？假想计算是什么？哪些标志改变？下一条条件指令检查什么？** 先练熟这条路线，再扩展到更多条件跳转。
