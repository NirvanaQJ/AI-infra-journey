## `phase_2`：六个整数与循环

使用 `objdump -d --disassemble=phase_2 ./bomb` 查看关卡，再查看 `read_six_numbers`。后者通过 `sscanf` 读六个整数；若成功转换的个数不超过 5 就调用 `explode_bomb`。输入从 `phase_2` 的 `%rsp` 开始存放，每个 `int` 占 4 字节。

| 栈中位置 | 数组元素 | 通过值 |
| --- | --- | ---: |
| `(%rsp)` | `a[0]` | 1 |
| `4(%rsp)` | `a[1]` | 2 |
| `8(%rsp)` | `a[2]` | 4 |
| `12(%rsp)` | `a[3]` | 8 |
| `16(%rsp)` | `a[4]` | 16 |
| `20(%rsp)` | `a[5]` | 32 |

`cmpl $0x1,(%rsp)` 要求 `a[0] == 1`。循环开始时 `%rbx = %rsp + 4`，指向 `a[1]`；`%rbp = %rsp + 24`，指向末尾之后。每轮把 `-4(%rbx)` 中的前一个数读入 `%eax`，`add %eax,%eax` 将它乘以 2，然后与 `(%rbx)` 中的当前数比较。每轮 `%rbx` 加 4，直到到达 `%rbp`，所以恰好检查 `a[1]` 至 `a[5]`。

等价条件是 `a[0] = 1` 且对 `i = 1..5` 有 `a[i] = 2 × a[i-1]`。据此得到输入：

```text
1 2 4 8 16 32
```

## `phase_3`：两个整数与跳转表

`objdump -d --disassemble=phase_3 ./bomb` 显示它调用 `sscanf`。GDB 静态查看 `x/s 0x4025cf` 得到格式串 `"%d %d"`；第一个整数存在 `8(%rsp)`，第二个在 `12(%rsp)`，成功转换个数必须大于 1。

`cmpl $0x7,0x8(%rsp)` 后接 `ja`，要求第一个整数按无符号比较不大于 7，因此允许值为 `0..7`，负数也被排除。`jmp *0x402470(,%rax,8)` 则按第一个整数索引跳转表：表项地址为 `0x402470 + 8 × 编号`。GDB 的 `x/8gx 0x402470` 给出以下目标地址；顺着目标处的 `mov` 指令可得预期的第二个整数：

| 第一个整数 | 跳转目标 | 第二个整数 |
| ---: | --- | ---: |
| 0 | `0x400f7c` | 207 |
| 1 | `0x400fb9` | 311 |
| 2 | `0x400f83` | 707 |
| 3 | `0x400f8a` | 256 |
| 4 | `0x400f91` | 389 |
| 5 | `0x400f98` | 206 |
| 6 | `0x400f9f` | 682 |
| 7 | `0x400fa6` | 327 |

以编号 1 为例：表的第二项指向 `0x400fb9`，在那里 `%eax` 被设为 `0x137 = 311`；汇合处将 `%eax` 与 `12(%rsp)` 的第二个输入比较。因此选择：

```text
1 311
```

关键教训：**表项顺序决定 `case` 编号，反汇编中的代码块排列顺序不决定编号。**

前三句分别证明前三关通过。最后的 EOF 来自程序继续读取第四关，而文件只提供三行；它不是第二、三关失败。当前执行环境不允许 GDB 用 `ptrace` 跟踪运行中的程序，因此本次使用静态反汇编、GDB 只读数据和直接运行验证，没有记录动态单步过程。
