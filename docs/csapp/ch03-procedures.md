# CSAPP 3.7：过程调用与栈帧

## 函数调用要完成什么

一次调用需要传递参数、跳到被调用函数、保存返回位置、管理局部数据，并在结束时把结果交回调用者。x86-64 的 `call` 将下一条指令的地址压栈并跳转；`ret` 从栈顶取回这个返回地址。每次递归调用都有自己的返回地址，因此返回顺序与调用顺序相反。

**通俗理解：**进入下一层工作前留一张“回来继续做”的纸条；内层先完成，再逐层取纸条返回。

## Linux x86-64 的参数与寄存器保存规则

常见整数和指针参数的前六个位置依次是 `%rdi`、`%rsi`、`%rdx`、`%rcx`、`%r8`、`%r9`；常见整数返回值使用 `%rax`。对应的 32 位 `int` 参数可写作 `%edi`、`%esi`、`%edx` 等。更多参数可能通过栈传递。这里讨论的是 Linux 上的 System V AMD64 调用约定。

| 类别 | 寄存器 | 跨调用的责任 |
| --- | --- | --- |
| 被调用者保存 | `%rbx`、`%rbp`、`%r12`～`%r15` | 若被调用函数要改动，返回前必须恢复旧值。 |
| 调用者保存 | `%rax`、`%rcx`、`%rdx`、`%rsi`、`%rdi`、`%r8`～`%r11` | 调用者若仍需要旧值，应在调用前自行保留。 |
| 栈指针 | `%rsp` | 返回时须恢复到调用方预期的位置。 |

`%rbp` 可以作为帧指针，也可以被编译器用于其他用途；必须根据真实指令判断。`push %rbx`、`pop %rbx` 是常见的保存与恢复方式。被调用函数若没有改动任何被调用者保存寄存器，就不需要为它们建立保存槽。

## 栈帧如何画

栈向低地址增长。`push` 先使 `%rsp` 减 8，再写入 8 字节；`sub $N,%rsp` 留出 `N` 字节；`add $N,%rsp` 释放这片空间。一次普通 `call` 还会额外压入 8 字节返回地址。判断某个栈槽的内容，要选定一个时刻的 `%rsp`，再计算偏移，不能把不同时间点的 `%rsp` 混为一谈。

在 System V AMD64 的常见调用中，执行 `call` 前 `%rsp` 为 16 字节对齐；`call` 压入 8 字节返回地址后，被调用函数入口的 `%rsp` 指向该地址。编译器可以省略传统的 `%rbp` 帧指针，所以“每个函数都必须有 `push %rbp; mov %rsp,%rbp`”并不成立。

### 仓库中的两个实例

- `phase_2` 开头 `push %rbp; push %rbx; sub $0x28,%rsp`。设此时 `%rsp=R`，六个 `int` 位于 `R+0x00` 至 `R+0x17`，旧 `%rbx` 在 `R+0x28`，旧 `%rbp` 在 `R+0x30`，返回地址在 `R+0x38`。这里 `%rbp` 随后被当作循环结束指针。
- `func4` 只有 `sub $0x8,%rsp` 和结尾对应的 `add $0x8,%rsp`，没有保存 `%rbx` 或 `%rbp`。它使用的参数和临时寄存器属于调用者保存组；每层递归调用都有新压入的返回地址与新预留的 8 字节。

## 分析递归时的四个问题

1. 本层收到的参数各是什么？
2. 哪个条件直接返回，哪个条件继续调用自身？
3. 递归调用改动了哪些参数？
4. 子调用返回后，本层如何加工 `%eax` 中的结果，最终返回到哪里？
