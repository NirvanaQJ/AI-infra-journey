# CSAPP 3.6：控制流、循环与 `switch` 跳转表

## 一条主线

C 的 `if`、循环和 `switch` 最终都要决定**下一条执行哪条机器指令**。读汇编时按这个顺序分析：输入存在哪里 → 哪条指令设置条件码 → 哪条跳转读取条件码 → 跳到哪里 → 哪条路径会失败或返回。

## 条件码和跳转

AT&T 语法的 `cmp S, D` 按 `D - S` 设置条件码，但不保存差值。例如 `cmpl $7, %eax` 比较 `%eax` 与 7。`je` 在零标志 `ZF=1` 时跳转；`jne` 在 `ZF=0` 时跳转。`jg` 是有符号大于，`ja` 是无符号大于；负数在无符号比较中会被解释成很大的数。

**通俗理解：**`cmp` 只写一张“比较结果便签”，条件跳转读便签后选择岔路。看见 `ja` 时，还要问程序是否借此排除了负数。

## 循环：找回边和停止位置

循环通常由条件检查、循环体、更新和跳回组成。反汇编中先找向较低地址跳转的指令，再找每轮变化的寄存器及退出条件。例如一个指针每次加 4，通常意味着逐个访问 4 字节的 `int`。结束指针若指向数组末尾之后，循环在当前指针到达它时停止。

**通俗理解：**拿手指逐格检查，走一格就回来判断是否还没到终点。要数清起点、终点以及每次移动的步长，才能确定循环执行几次。

## `switch`：按表项而非代码排列顺序还原

密集的 `case` 可能被编译成跳转表。形式如 `jmp *BASE(,%rax,8)`：先计算 `BASE + %rax × 8`，从该地址取出一个 64 位代码地址，再跳过去。`%rax` 是表下标，比例 8 是每个地址占 8 字节。通常还有一次范围检查，让越界值走向 `default`。

**通俗理解：**先用编号查目录，再翻到目录记录的页码。目录第几项对应哪个 `case`；下面代码块在文件里排列的先后不代表 `case` 顺序。

反推时逐项记录：`case` 编号 → 表项地址 → 目标代码地址 → 该分支设置的值或执行的操作 → 汇合处的最终检查。`break`、共用代码块和编译器优化都可能改变代码形状，因此以真实指令为准。
